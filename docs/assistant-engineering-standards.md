# Agent 工程标准

适用于管理助手及其直接调用链。正确性、安全性、可恢复性和可访问性是前提；随后比较维护成本、复用程度与界面质量。现有约定和官方示例都需要结合当前业务验证，不作为自动正确的依据。

## 职责与目录

| 位置                              | 应负责                                               | 不应负责                                         |
| --------------------------------- | ---------------------------------------------------- | ------------------------------------------------ |
| server `assistant/domain`         | 会话、请求、操作的本地类型、仓库端口与错误           | Pi、AG-UI、Prisma、HTTP 结构                     |
| server `assistant/application`    | 所属关系、去重、生命周期、取消、保存、已有端口的编排 | SDK 解析、供应商配置、SSE 编码、具体基础设施实现 |
| server `assistant/infrastructure` | Pi 适配、业务工具适配、Prisma、供应商消息解析与投影  | 替代管理员授权、在模型文字中认定业务成功         |
| server `assistant/presentation`   | HTTP 边界校验、鉴权接入、错误与 AG-UI 映射           | 自行执行工具、直接修改评论                       |
| admin `features/assistant`        | 对话流程、状态协调、业务结果组件和局部交互           | 后端领域模型、任意生成式代码或组件执行           |
| `packages/contracts`              | 跨应用 HTTP 请求、响应与公开结果类型                 | Pi/Prisma/Nest 内部类型                          |

模块入口只负责组装。前端先按业务功能聚合；可复用基础控件使用现有 `components/ui`，Markdown 使用共享包。只有出现独立职责时才拆组件或文件，不按行数硬切，也不预建空的 services、hooks、utils 目录。

单元和组件测试与源码相邻；真实数据库与 HTTP 测试放在 `apps/server/test`；评测脚本放在 `apps/server/scripts`。文档和历史验收结果不进入运行时模块。

## 复用与代码减法

实现前依次检查：能否省略或删除、能否复用项目能力、能否使用平台或已安装 SDK，最后才手写。新增依赖必须解决实际问题，并核对维护状态、运行环境、包体和部署结果；不为少量普通代码增加包。

- Pi 管模型与工具循环、协议解析及工具 schema 校验；AG-UI SDK 管事件传输。不保留平行实现或开发期协议解析原型。
- 本项目保留业务语义，例如有效日历日期、筛选互斥、权限和事务；不要把它们误删为“SDK 已校验”。
- 只有真实消费者才保留导出、事件字段、配置与包装。测试应验证上线路径，不能为无调用 helper 创造用途。
- 不为一个实现机械增加接口；跨运行时、存储或授权边界的已有端口保留，测试替身也应经过这些边界。
- 自写实现若提供 SDK 没有的必要语义，应保留并说明。例如运行时队列的消费者确认用于保证先持久化，再继续或公开结果，不能用普通事件队列替换。
- 命名表意，尽早处理无效状态，避免嵌套和隐式状态组合。注释解释原因与约束，不逐句翻译代码。不以压缩行数代替可读性。

每次评审同时说明删掉了什么、新增部分为何必要、调用方和失败行为如何验证。目录移动不计为复杂度减少。

## 不可退让的执行边界

- 身份来自服务器会话；客户端历史、工具参数、URL 标识都不能替换管理员身份或越过所属关系。
- 每次工具前复核授权。已发现授权失效时终止整轮，不把权限失败作为模型可修正的普通参数问题。
- 对话、请求、工具和操作身份有明确作用域。同身份重试核对既有记录，不另起一次业务效果。
- PostgreSQL 是状态与回执依据；终端事件、文字、EOF、工具参数结束都不能取代业务提交结果。
- 取消与完成使用条件更新。等待实际工作收束；迟到的停止和旧页面回包不能覆盖新请求。
- 修改评论前必须有明确预览和人工决定；版本检查、业务修改、审计与回执同事务。未知提交结果按原身份恢复。
- 供应商消息是适配器内部数据；解析时检查版本和形状，不把任意 JSON 强转为可信 SDK 消息。公开输出和日志不泄漏思考正文、凭据或原始敏感字段。
- 助手 Markdown 禁止自动嵌入图片，覆盖历史、流式和预加载；使用渲染器原生限制，不自写正则清洗。普通链接保留显式点击，文章渲染使用自己的信任策略。
- 明确单实例边界、时间和调用预算、查询分页及结果体积上限。进程重启不自动重放写入；增加副本或持续任务前重新设计执行所有权。

## 测试是否需要

不要求每个文件配一个测试，也不以覆盖率或数量作为验收结论。根据失败后果选择层级：

| 风险或行为                                 | 最小有意义的验证                                     |
| ------------------------------------------ | ---------------------------------------------------- |
| 所属关系、权限撤销、伪造输入、公开字段     | 实际控制器或真实 HTTP 边界，断言业务未执行及最终状态 |
| Pi 事件、参数校验、取消、持久化屏障        | 真实 SDK 配可控上游，断言请求次数、顺序与停止效果    |
| 唯一索引、条件更新、并发确认、审计失败回滚 | 独立 PostgreSQL，验证提交或回滚后的真实数据          |
| 刷新、路由切换、未知提交、审批状态         | 可控异步组件或 hook 回归，覆盖迟到成功和失败         |
| Cookie、请求身份、确认 payload             | 精炼的 API 契约测试，避免目标或执行者可替换          |
| 布局、焦点、键盘、滚动、深浅主题           | 真实浏览器；假数据验证只证明 UI，另做真实链路验证    |
| 纯转发、无行为声明、开发期原型             | 不机械加测试；合并重复断言，删除只测试自身的副本     |

修 bug 先构造会失败的用例，再验证修复。测试模拟外部边界，不重写一份被测算法。数据库测试不访问真实业务库；共享数据库的启动收束和锁等待测试串行执行，清理自己的资源。

模型、提示词或工具语义改变时，选择相应真实模型评测；纯目录移动不能冒称重新验证了模型正确率。历史评分、失败探针和评测版本保留，不改分数来满足门槛。

## 交互与视觉验收

- 加载、新会话、无结果、读取失败、生成中、停止中、结果未知和已提交分别表达；加载失败不能伪装新会话。
- 长对话下输入与停止可达。进入会话定位最新，靠近底部才跟随生成，向上阅读不被拉走，加载更早保留阅读位置。
- 输入限制与服务器一致；保留中文输入法和换行，快捷键有说明，示例和复用问题回到输入焦点。所有按钮有键盘焦点和清楚名称。
- 操作未知时保留原决定和原身份，只核对或重试同决定；未核对前不开放相反动作。加载反馈属于实际点击的按钮。
- 已确认回执与当前资源状态分开表达，回答完成不代表写入成功。
- 延续编辑型工作台的字体、颜色、间距、控件和深浅主题；减少重复标题与装饰卡片。正文限制可读宽度，长链接和评论不裁切。
- 在桌面、窄屏、长内容、错误和审批状态查看实际截图；不能只看空态或只凭构建通过验收美观。

## 组织与发布

负责人明确修改范围和文件所有者，先审查再实现；并行工作不互相覆盖，也不改用户已有未提交文件。作者不能仅凭自己的“通过”结论结束：做交叉评审，负责人核对关键路径、截图和未决问题。

合入前完成适用的 `vp check`、`vp test`、构建和独立数据库回归。优先消除问题根因，不扩大到无关模块。记录当前验证的版本、假数据与真实链路的边界；发布保留可用回退路径，生产验证只读业务数据，验收后清理临时资源。
